# 🎉 PartyBox

**みんなで遊べる、かんたんオンラインゲーム。**
URLを送るだけで、友達とすぐにブラウザで遊べるパーティーゲーム集です。Discord などで通話しながら遊ぶことを想定しています。
1人で遊べる 3D レース「プロンプト・グランプリ」も、同じトップページから遊べます（入り口は1つ）。

```
サイトを開く → ゲームを選ぶ → ルームを作る → URL/コードを共有 → 友達がスマホで参加 → 全員そろったら開始 → 結果発表 → もう一回
```

## 遊べるゲーム

| ゲーム | ジャンル | 人数 | 概要 |
|---|---|---|---|
| 🕵️ 誰の答えでしょう？ | 心理戦 | 3〜8人 | 匿名で集めた回答の「書いた人」を当て合う |
| 🤝 全員一致を目指せ！ | 協力 | 3〜10人 | みんなと同じ答えを書いてチーム得点を狙う |
| 🎭 嘘つきは誰だ？ | 正体隠匿 | 4〜8人 | 1人だけお題を知らない嘘つきを話し合いで暴く（ワードウルフモードあり） |
| 🎨 回答を育てろ | お絵描き | 3〜8人 | 絵 → 文章 → 絵… と伝言し、最後にアルバムで振り返る |
| ⚖️ 10秒裁判 | 会話 | 4〜8人 | 被告・検察・弁護士・証人になって10秒ずつ発言し、有罪/無罪を判決 |
| 🏎️ プロンプト・グランプリ | ひとりで・レース | 1人 | 「こんな車」と書くと 3D のミニカーが生まれ、CPU とレース。応援して観戦する（ルーム不要。`/grand-prix/`。詳しくは [grand-prix/README.md](grand-prix/README.md)） |

このほかに、司会が進行する催し物向けの **[懇親会](#懇親会社内の余興など)**（クイズ・座席決め・ビンゴ）があります。
トップページの「懇親会・催し物」の欄から、ルームを作る（`/play/party-event`）か、デモで1人で試せます（`/demo/party-event`）。

## クイックスタート

```bash
npm install

# 開発（サーバー :3001 + Vite :5173 を同時起動）
npm run dev
# → http://localhost:5173（プロンプト・グランプリは http://localhost:5173/grand-prix/）

# 本番ビルド & 起動（1つのポートで画面とWebSocketを配信）
npm run build
npm start
# → http://localhost:3001
```

> 開発を引き継ぐ方（AI エージェントを含む）は、先に [CLAUDE.md](CLAUDE.md) を読んでください。進め方・壊してはいけない所・決めたことの理由・既知の問題を書いています。

### スマホから参加するには

- **同じWi-Fi内**: `npm run dev` 中に `http://<PCのIPアドレス>:5173` を開く（Vite は `host: true` で起動します）
- **インターネット越し**: 下記「デプロイ」を参照。Render / Railway / Fly.io など WebSocket が使える Node.js ホスティングに `npm run build && npm start` でそのまま載ります。Docker も用意しています。

## 設計

### ページ構成（入り口は1つ）

| URL | ページ | 中身 |
|---|---|---|
| `/` `/play/:id` `/join` `/room/:code` | `index.html` | PartyBox（React の SPA）。トップのゲーム一覧に全ゲームのカードが並ぶ |
| `/demo/:id` | `index.html` | 催し物（懇親会）のデモ。司会と参加者の画面を iframe で並べる（[デモ](#デモ1人で試す)） |
| `/grand-prix/` | `grand-prix/index.html` | プロンプト・グランプリ（Three.js）。トップのカードから通常のリンクで開き、左上の「← PartyBox」で戻る |

- Vite のマルチページビルドで2つのページを一緒にビルドし、1つのサーバー（1つのポート）から配信します。three.js は別ファイルに分かれ、PartyBox のページでは読み込まれません。
- サーバーは `/grand-prix` などを `/grand-prix/` に転送し、それ以外の URL は SPA（`index.html`）を返します。
- 1人用のゲームはルームを使わないので、カタログは `shared/games.ts` の `SOLO_GAMES`（`GAMES` とは別）にあります。

### リアルタイム通信（サーバー権威型）

- クライアントは **操作（アクション）だけ** を送り、得点計算・勝敗判定・フェーズ進行はすべてサーバーで行います。
- サーバーは状態が変わるたびに、**プレイヤーごとに秘匿情報を取り除いたビュー** を生成して送信します。
  - 例: 回答フェーズ中は他人の回答内容は送らない（「誰が送信済みか」だけ送る）／嘘つきの正体・証拠カード・推理対象の作者は本人以外に送らない
- 同一 tick 内の複数の変更はまとめて1回だけ配信します（`Room.requestBroadcast`）。
- **タイマー同期**: サーバーは「締切時刻（サーバー時刻）」を配信し、クライアントは `serverNow` との差分で時計のずれを補正してカウントダウンします。締切直前には入力中の内容を自動送信し、サーバーは少しの猶予を持って締め切ります。

| クライアント → サーバー | 内容 |
|---|---|
| `room:create` / `room:join` / `room:rejoin` | ルーム作成・参加・再接続 |
| `room:settings` / `room:changeGame` / `room:start` | ホストの設定・ゲーム変更・開始 |
| `room:kick` / `room:close` / `room:leave` / `room:rename` | キック・ルーム削除・退出・名前変更 |
| `room:restart` / `room:backToLobby` | もう一回・ロビーへ |
| `game:action` | ゲーム内操作（回答・投票・発言など。`{ type, ... }`） |

| サーバー → クライアント | 内容 |
|---|---|
| `room:state` | そのプレイヤー用のルームビュー（参加者・設定・ゲーム状態・締切） |
| `room:closed` / `room:kicked` / `session:replaced` | ルーム削除・キック・別タブ接続の通知 |

### 共通ルームシステム

- 6桁のルームコード（読み間違えやすい `0/O/1/I/L` を除外）と招待URL `/room/<CODE>`、QRコード
- 参加時に **playerId + 秘密トークン** を発行し、`localStorage` に `roomCode / playerId / token / name` を保存
  - リロード・回線切断時は自動で再接続し、同じプレイヤーとして復帰（トークンで本人確認、なりすまし防止）
  - 同じプレイヤーが別タブで接続した場合は古いタブを切り離す
- 切断したプレイヤーは一定時間（既定3分）ルームに残り、その間に戻れば復帰。戻らなければ自動退出
  （懇親会のルームだけは退出させない。[回線が切れたとき](#回線が切れたとき)を参照）
- ホストが退出/切断したら、接続中の最古参プレイヤーへホスト権限を自動移譲
- ホスト権限: ゲーム開始・設定変更・ゲーム変更・キック・ルーム削除・進行（次へ/スキップ）・中断
- ゲーム中に参加した人は観戦者として入り、次のゲームから参加

### ゲーム状態管理（`BaseGame`）

```
LOBBY → START → (ROUND → ANSWER → RESULT) × N → GAME_OVER → もう一回 / ロビー
```

- `setPhase(phase, { duration, grace, onEnd })` で各フェーズを定義。**時間切れ・全員完了・ホストのスキップ** はすべて同じ `advance()` を通るため、二重進行が起きません。
- 途中退出したプレイヤーは完了判定から除外され、ゲームは止まりません。人数が最低人数を下回った場合は安全にゲームを終了します（例: 嘘つき本人が退出 → そのラウンドは無効）。
- フェーズ遷移中の例外はキャッチしてゲームを終了扱いにし、サーバー全体がクラッシュしないようにしています。

## 懇親会（社内の余興など）

数十人が集まる催し物を、司会の進行で動かすための企画です。
クイズ（夕食）・座席決め（二次会）・ビンゴ（二次会）が **ひとつのルームに同居**していて、
司会が行き来しても、引いた番号・決まった席・クイズの進行は消えません。

| 企画 | 参加者のスマホ | 司会の画面 |
|---|---|---|
| 📝 クイズ | チームを選んで答える（押し間違えたら「変える」で選び直せる）。**答えは「答え」の段までサーバーから配られない** | 問題 → 回答タイム → 答え を進める。**答えは問題の段から司会にだけ小さく出る**（司会の画面を会場に映すとネタばれになるので注意）。選択肢は自動採点、自由回答は ○ を付ける。同点なら同点優勝 |
| 🪑 座席決め | 名簿から自分を選んで待つ（**名簿に無ければ自分で名前を足せる**）。引かれるとテーブルと同席者が大きく出る | 1人ずつ本当のくじ。**名前を選んだ人だけ**が対象で、所属が混ざるように入る。残り全員・取り消し・欠席も |
| 🎱 ビンゴ | 1人1枚のカード。マスは自動で開く。「ビンゴ！」はサーバーが検証する | 番号を引く。到着順に並ぶ。カードIDから同じカードを出して確かめる。景品のくじ引きも（引き直すときは確認が出る） |

### 司会用URL

ルームを作ると、ロビーに **司会用URL**（`/room/<CODE>/h/<24文字>`）が出ます。
これを開いた人が進行役になります。**司会の方にだけ**渡してください。
始めたあとも、司会の画面の「📱 参加用のQR・URL」から、参加用のQR・URLと司会用URLを出せます（遅れて来た人に見せる）。

- 複数人・複数端末で司会できます（司会を2〜3人で分担する想定）。司会用URLを開いた人は、ロビーの「ゲーム開始」も押せます
- 「次へ」「引く」「戻す」を二度押ししても、司会2人が同時に押しても、1回ぶんしか進みません
  （画面が見ていた状態を操作に付けて送り、もう進んだあとに届いた操作はサーバーが何もしない）
- 回線が切れても司会のまま。通常のゲームと違い、参加者にホストが自動で移りません
- ルームを作った人が「退出」しても、参加者は司会になりません（司会用URLを開いた人にだけ移ります）
- 参加者が進行の操作を送っても、サーバーが弾きます
- 懇親会のルームには「ゲームを中断してロビーに戻る」がありません（戻すとクイズ・座席・ビンゴの進行が全部消えるため。サーバーでも弾きます）。
  やり直したいときは各企画の「最初から」を使います

### 名簿・問題の置き場

**名簿には実名と所属が入るため、このリポジトリには置きません。**
サーバー上の置き場に `quiz.json` / `bingo.json` / `seats.json` を入れてください。

```bash
# 既定の置き場（環境変数 PARTYBOX_EVENT_DATA_DIR で変更可）
scp quiz.json bingo.json seats.json <サーバー>:/opt/partybox/event-data/
```

- 置き場にファイルが無ければ、同梱の**サンプル**（`server/event/sample/`）で動きます
- 置き場にあるのに形式が違う場合は、黙ってサンプルに落とさず**起動を失敗させます**
  （当日「なぜかサンプルの問題が出た」を防ぐため）
- 形式は party-app-aws の `data/*.json` と同じなので、そのまま持ってこられます
  （クイズの選択問題の `answer` は**何番目か（1 始まり）**。範囲外の番号は起動時のエラーにします）

```jsonc
// quiz.json
{ "title": "懇親会クイズ", "secondsPerQuestion": 30, "teams": ["チーム A", "チーム B"],
  "questions": [
    { "question": "…", "choices": ["あ", "い"], "answer": 1, "note": "解説" }, // 選択問題（自動採点）。answer は何番目か（1 始まり）
    { "question": "…", "answer": "こたえ" }                                     // 自由回答（司会が ○）
  ] }
// bingo.json  … seed は当日変えないこと（変えると配ったカードが別物になる）
{ "title": "ビンゴ", "seed": "2026-11", "winnersCount": 6, "prizes": ["…"] }
// seats.json
{ "title": "座席決め", "participants": [{ "name": "…", "group": "…" }],
  "tables": [{ "name": "テーブル 1", "seats": 8 }] }
```

### 進行が消えないようにする

懇親会のルームだけ、状態をディスクに書いて再起動時に読み戻します（`server/rooms/persist.ts`）。
**まだ「ゲーム開始」を押していないルームも保存します**（前日に作って QR と司会用URLを配ったあとで再起動しても、そのまま使えます）。
参加者の端末は `localStorage` のセッションで自動的に再参加するので、**サーバーを再起動しても
引いた番号・決まった席・クイズの進行・手元のカードはそのまま**です。

```bash
PARTYBOX_STATE_DIR=/opt/partybox/state   # 既定。Docker では必ずホスト側と共有すること
```

> `deploy/aws/partybox.yaml` は `state` と `event-data` をホストから渡すようにしてあります。
> 自分で `docker run` する場合は `-v` を忘れないでください（忘れると再デプロイで進行が消えます）。

### 座席決めのくじに入る人

名簿には来ない人も載っているので、くじは**来ている人だけ**から引きます（来ない人で席が埋まらないように）。

- 参加者が自分のスマホで**名簿から名前を選んだ人**
- 名簿に無く、**自分で名前を足した人**（「名簿に名前が無い方はこちら」から。所属は名簿にある所属か「その他」から選ぶ。
  1人1件で、もう一度足すと打ち間違いの直しになる。名簿にある名前は足せない）。
  足したあとで名簿の自分を選び直した場合、足した名前は誰も選んでいないので引きません
- 司会が「名簿に無い人を足す」で足した人
- 司会が「名前を選んでいない人」から**タップしてくじに入れた人**（スマホが無いなど、自分で選べない人）

司会が欠席にした人は、これらに当たっても引きません。司会の画面の「くじに入る人」が対象の一覧です。
みんなが名前を選び終わってから引いてください。

- 別のスマホがもう選んでいる名前には「選ばれています」と出ます。押すと「ご本人ですか？」と確かめてから、
  こちらのスマホに移します（別のブラウザで開き直した本人や、他の人に間違えて選ばれた本人が取り戻せるように）。
  前のスマホは名前の選び直しになります
- 「退出」した人が選んでいた名前は空きます（くじからも外れます）

### 回線が切れたとき

スマホの画面を消している間は回線が切れるのが当たり前なので、懇親会のルームは通常のゲームと扱いを変えています。

- 切断した人を**ルームから外しません**。画面を点ければ同じ人として戻り、ビンゴのカードもそのまま
- 切断している人と同じ名前では入れます（LINE で開いたあと Safari で開き直した、など別のブラウザから入り直した本人のため）。
  接続している人とは同じ名前にできません
- 司会も含めて全員が切断していても、**ルームは消しません**（前日に作って QR を配っておける。夕食と二次会のあいだに全員の画面が消えていても残る）。
  最後の動きから **7日**たったルームだけ片付けます（再起動しても延びません。片付けたルームは保存ファイルからも消します）。
  端末に残す参加情報も8日もつので、前日に入った人は当日そのまま戻れます
- 懇親会のルームと通常のゲームは、ロビーの「ゲーム変更」で行き来できません（サーバーでも弾きます）
- 電波が弱くて返事が来なかっただけのときは、参加情報を消さずにつなぎ直します（別の人として入り直しにならない）。
  画面を点けたときにも一度たずねて、回線が固まっていればつなぎ直します
- 同じブラウザの別のタブで開くと、前のタブは止まります。前のタブには「この画面で続ける」が出て、どちらでも続けられます

### デモ（1人で試す）

`/demo/party-event`（トップの「デモで試す」）を開くと、**司会の画面と参加者の画面（1〜5台）が並び**、
司会の枠で「引く」「次へ」を押すと参加者の枠が同時に変わります。人を集めなくても進行を確かめられます。

- どの枠も本物の画面で、本物のサーバーに繋がります。枠は `?seat=<枠>` で**別の端末**として扱われ、
  同じブラウザでもカード・名前・回答が混ざりません（`client/lib/session.ts` が保存のキーを枠ごとに分ける）
- 開くたびに**使い捨てのデモ用ルーム**を作ります。本番のルームには触れません。
  ディスクに保存せず、誰もいなくなって30分で片付きます
- 「スマホで参加」の QR から、手元のスマホでデモに加わることもできます
- 名簿と問題は本番と同じもの（置き場のデータ）を使います

> トップページから誰でも懇親会のルームとデモを作れるので、**URL を知っている人は名簿とクイズ（答えを含む）を見られます**。
> 当日まで答えを伏せたい場合は、置き場にクイズを入れるのを直前にしてください。

### 当日の流れ

1. 司会がトップの「懇親会・催し物」→「ルームを作る（司会）」（`/play/party-event`）でルームを作る
2. ロビーの**招待URL（QRコード）**を参加者に、**司会用URL**を司会の方に配る
3. 全員そろったら「ゲーム開始」。あとは司会が企画を切り替えながら進める
   （開始したあとに来た人も、そのまま参加者になります）

## 拡張方法

### お題を追加する

`server/data/` の JSON を編集するだけです（再ビルドで反映）。

| ファイル | 内容 |
|---|---|
| `unanimous.json` | 全員一致のお題（`prompts` に文字列を追加） |
| `whose-answer.json` | 誰の答えの質問（`questions`） |
| `liar.json` | 嘘つきのお題（カテゴリごと。同カテゴリ内が推理の選択肢・ワードウルフの別お題になる） |
| `grow-answer.json` | お絵描きの最初のお題（`prompts`） |
| `trial.json` | 裁判の事件テンプレート。`{d}` は被告名、`{変数}` は `vars` からランダムに選ばれる。`guilty` / `innocent` が証拠カード |

同じルームで遊んでいる間は、お題を使い切るまで同じものは出ません。

### ルール・人数・時間を変更する

- 人数・所要時間・設定の選択肢: `shared/games.ts` の該当ゲームを編集
- 得点: 各ゲームファイルの定数（`WHOSE_POINTS`, `LIAR_POINTS`, `TRIAL_POINTS`, `unanimousPoints()`）

### 新しいゲームを追加する

（以下はルームで遊ぶゲームの場合。1人用のゲームは `shared/games.ts` の `SOLO_GAMES` にカードの情報を足し、ページを `vite.config.ts` の `PAGES` とサーバーの配信に加える）

1. `shared/games.ts` の `GameId` と `GAMES` にメタ情報を追加 → **トップページのカード・ロビーの設定UIに自動で反映**
2. `shared/games/views.ts` にビュー型を追加
3. `server/games/<id>/` に `BaseGame` を継承したクラスを作り、`server/games/registry.ts` に1行登録

   ```ts
   export class MyGame extends BaseGame<'START' | 'ANSWER' | 'RESULT' | 'GAME_OVER'> {
     readonly gameId = 'my-game' as const;
     protected beginGame() {
       this.setPhase('ANSWER', { duration: 30_000, onEnd: () => this.showResult() });
     }
     protected onAction(playerId: string, action: GameAction) { /* 入力を検証して状態を更新 */ }
     getView(playerId: string) { return { ...this.baseView(playerId), /* 本人に見せてよい情報だけ */ }; }
   }
   ```
4. `client/games/<id>/` に画面を作り、`client/games/registry.tsx` に1行登録（共通部品 `PhaseHeader` / `AnswerForm` / `SubmissionStatus` / `Scoreboard` / `GameOverPanel` などを利用可能）

## デプロイ

### AWS Lightsail（おすすめ）
`deploy/lightsail/partybox.yaml` を CloudFormation でアップロードすると、Lightsail 1台 + 自動HTTPS で公開できます。
手順は [deploy/lightsail/README.md](deploy/lightsail/README.md)。

| | 月額の目安 | 中身 |
|---|---|---|
| **Lightsail `micro_3_0`** | **$7.00** | 2vCPU / 1GB / SSD 40GB / 転送 2TB・固定IP込み |
| EC2 t4g.micro（旧構成） | 約 $13.5 | EC2 $7.88 + 固定IP $3.65 + EBS 20GB $1.92 |

転送量と固定IPが料金に含まれるぶん Lightsail のほうが安く、構成も単純です。

### AWS EC2（旧構成）
VPC やセキュリティグループを自分で持ちたい場合は [deploy/aws/README.md](deploy/aws/README.md)。
機能は同じですが、固定IPと転送量が別料金です。

### Docker
```bash
docker build -t partybox .
docker run -p 3001:3001 partybox
```

| 環境変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `3001` | 待ち受けポート |
| `HOST` | （全インターフェース） | 待ち受けアドレス |
| `PARTYBOX_TIME_SCALE` | `1` | ゲーム内時間の倍率（動作確認用。`0.5` で半分の時間） |
| `PARTYBOX_STATE_DIR` | `/opt/partybox/state` | 懇親会のルームの保存先（[懇親会](#懇親会社内の余興など)を参照） |
| `PARTYBOX_EVENT_DATA_DIR` | `/opt/partybox/event-data` | 懇親会の名簿・問題の置き場 |

**注意**: ルームの状態はサーバーのメモリに持っていて、インスタンスは1台で動かす前提です
（複数台にする場合は Socket.IO の Redis Adapter と状態の外部化が必要）。
遊びのルームは再起動で消えます。**懇親会のルームだけ**はディスクに保存して読み戻します。
